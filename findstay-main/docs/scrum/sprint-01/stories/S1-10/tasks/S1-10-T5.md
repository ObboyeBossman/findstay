## 1. Outcome & Objective

Expose authenticated backend endpoints so signed-in users can:
1. View their own in-app notifications inbox with unread counts for the header bell badge (`GET /api/v1/me/notifications`).
2. Mark a single notification as read (`POST /api/v1/me/notifications/{id}/read`).
3. Mark all unread notifications as read (`POST /api/v1/me/notifications/read-all`).
4. Read and update per-event, per-channel preferences (`GET /api/v1/me/notifications/preferences` and `PUT /api/v1/me/notifications/preferences`).

All endpoints are strictly scoped to the authenticated caller's JWT `sub` UUID, completely preventing cross-user alert leakage or modification (IDOR mitigation per `NFR-24`).

---

## 2. API Contract Specification

All endpoints reside under `/api/v1/me/notifications` and require valid JWT authentication. All timestamps are formatted in ISO-8601 UTC (`TIMESTAMPTZ`). Errors conform to the standard FindStay `ApiError` format.

### 2.1 GET `/api/v1/me/notifications`
- **Query Parameters:**
  - `limit` (int, default `20`, min `1`, max `100`): Page size.
  - `offset` (int, default `0`, min `0`): Pagination offset.
- **Ordering:** Newest first (`created_at DESC`).
- **Response Shape (200 OK):**
```json
{
  "items": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "recipientId": "11111111-1111-1111-1111-111111111111",
      "eventType": "VERIFICATION_STATUS_CHANGED",
      "title": "Verification Approved",
      "message": "Your owner verification documents have been approved.",
      "data": "{\"caseId\":\"...\"}",
      "readAt": null,
      "createdAt": "2026-11-22T20:00:00Z"
    }
  ],
  "total": 1,
  "unreadCount": 1
}
```

### 2.2 POST `/api/v1/me/notifications/{id}/read`
- **Path Parameter:** `id` (UUID) - Target notification ID.
- **Behavior:**
  - Sets `read_at = clock_timestamp()` if `recipient_id == caller.sub` and `read_at IS NULL`.
  - Returns `404 Not Found` if notification does not exist OR belongs to another user (anti-enumeration / IDOR prevention).
- **Response Shape (200 OK):**
```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "recipientId": "11111111-1111-1111-1111-111111111111",
  "eventType": "VERIFICATION_STATUS_CHANGED",
  "title": "Verification Approved",
  "message": "Your owner verification documents have been approved.",
  "data": "{\"caseId\":\"...\"}",
  "readAt": "2026-11-22T21:00:00Z",
  "createdAt": "2026-11-22T20:00:00Z"
}
```

### 2.3 POST `/api/v1/me/notifications/read-all`
- **Behavior:** Marks all unread alerts for the signed-in caller as read in one atomic transaction.
- **Response Shape (200 OK):**
```json
{
  "updatedCount": 4
}
```

### 2.4 GET `/api/v1/me/notifications/preferences`
- **Behavior:** Retrieves caller's per-event, per-channel delivery preferences. Returns system defaults if not explicitly customized yet.
- **Response Shape (200 OK):**
```json
{
  "preferences": [
    {
      "eventType": "VERIFICATION_STATUS_CHANGED",
      "emailEnabled": true,
      "smsEnabled": false,
      "inAppEnabled": true
    },
    {
      "eventType": "LISTING_STATUS_CHANGED",
      "emailEnabled": true,
      "smsEnabled": false,
      "inAppEnabled": true
    },
    {
      "eventType": "ACCOUNT_ACTIVITY",
      "emailEnabled": true,
      "smsEnabled": false,
      "inAppEnabled": true
    }
  ]
}
```

### 2.5 PUT `/api/v1/me/notifications/preferences`
- **Request Body:**
```json
{
  "preferences": [
    {
      "eventType": "VERIFICATION_STATUS_CHANGED",
      "emailEnabled": true,
      "smsEnabled": true,
      "inAppEnabled": true
    }
  ]
}
```
- **Response Shape (200 OK):** Returns the persisted preferences.

## 3. Database Schema (`V1_11__notification.sql`)

- Added schema `notification` within Sprint 1 Flyway range (`V1_01`–`V1_19`).
- `notification.notification`:
  - `id` (UUID PK)
  - `recipient_id` (UUID, indexed with `created_at DESC`)
  - `event_type` (VARCHAR(100))
  - `title` (VARCHAR(255))
  - `message` (TEXT)
  - `data` (JSONB)
  - `read_at` (TIMESTAMPTZ, partial index on unread alerts)
  - `created_at` (TIMESTAMPTZ)
- `notification.notification_preference`:
  - `id` (UUID PK)
  - `user_id` (UUID, indexed)
  - `event_type` (VARCHAR(100))
  - `email_enabled` (BOOLEAN)
  - `sms_enabled` (BOOLEAN)
  - `in_app_enabled` (BOOLEAN)
  - `created_at` / `updated_at` (TIMESTAMPTZ)
  - UNIQUE `(user_id, event_type)`
- `notification.notification_template`:
  - Templates keyed by `(event_type, channel)` for public `NotificationSender` seam.
