## 1. Outcome & Objective

Build FindStay's shared `NotificationSender` dispatcher and swappable Email / SMS provider adapters so any backend module (`organization`, `verification`, `listing`, `admin`) can trigger in-app, email, and SMS alerts reliably. Failed outbound deliveries are recorded in PostgreSQL (`notification.notification_delivery`) and automatically retried using exponential backoff with a max-attempts cap, with safe email-only fallback when Ghana SMS sender-ID is not active (Settled Decision `P-08`).

---

## 2. Architecture & Module Seams

- **Public Seam (`com.findstay.notification.api` - Extension Seam 4):**
  - `NotificationSender`: Dispatcher interface with `send(NotificationRequest request)`.
  - `NotificationRequest`: Immutable DTO accepting `recipientId`, `eventType`, `title`, `message`, `data`, `recipientEmail`, and `recipientPhone`.
- **Internal Dispatcher (`com.findstay.notification.internal`):**
  - Evaluates user channel preferences (`email_enabled`, `sms_enabled`, `in_app_enabled`) from `notification_preference`.
  - Persists in-app inbox row in `notification.notification` (`read_at = NULL`).
  - Renders multi-channel copy using `TemplateRenderer` from `notification_template`.
  - Dispatches outbound EMAIL via `EmailProviderAdapter` and SMS via `SmsProviderAdapter`.
  - Records delivery state (`QUEUED`, `SENT`, `FAILED`) in `notification_delivery`.
- **Shared Kernel (`com.findstay.shared`):**
  - `IdGenerator`: UUIDv7 generator.
  - `Clock`: UTC timestamp provider with Africa/Accra zone support.
  - `BackgroundJobs`: Background job scheduler wrapper.

## 3. Swappable Provider Adapters & Decision P-08 Fallback

Swapping providers is controlled purely via configuration (`application.yml` and environment variables), requiring zero business-logic edits:

### 3.1 Email Adapters (`EmailProviderAdapter`)
1. `LogEmailProviderAdapter`: Standard local development/test adapter that logs outbound email messages.
2. `SmtpEmailProviderAdapter`: Outbound SMTP/Resend provider adapter configured via `NOTIFICATION_EMAIL_PROVIDER=smtp`.

### 3.2 SMS Adapters & P-08 Fallback (`SmsProviderAdapter`)
1. `GhanaSmsProviderAdapter`: Formats and delivers SMS alerts to Ghana (+233) numbers using configured sender ID.
2. `NoopSmsProviderAdapter` (Settled Decision `P-08` Fallback):
   - When SMS is switched off (`NOTIFICATION_SMS_ENABLED=false`) or sender-ID approval is pending, this adapter gracefully skips SMS dispatch without raising errors.
   - Ensures in-app and email alerts succeed uninterrupted.

## 4. Delivery Logging & Automated Retry Sweep

- **Table:** `notification.notification_delivery`
  - Columns: `id`, `notification_id`, `recipient_id`, `channel`, `destination`, `subject`, `body`, `status`, `attempts`, `max_attempts`, `last_attempt_at`, `next_retry_at`, `provider_message_id`, `last_error`.
  - Constraints: `channel IN ('EMAIL', 'SMS')`, `status IN ('QUEUED', 'SENT', 'FAILED')`.
- **Retry Processor (`NotificationRetryProcessor`):**
  - Periodically queries `status = 'FAILED' AND next_retry_at <= now()`.
  - Re-dispatches using the appropriate channel adapter.
  - On success: transitions to `SENT`, clears `next_retry_at`, records `provider_message_id`.
  - On failure: increments `attempts`, updates `last_error`, applies exponential backoff (`delay = 2^attempts * 60s`), and caps at `max_attempts = 3`.
