## 3. Specification Highlights

1. **Header Notification Bell & Badge:**
   - Evaluates count states: `0` (hidden), `1–99` (pill with count), and `99+` (compact overflow-safe badge).
   - WCAG 2.1 AA compliant touch targets (min 44px × 44px) and screen reader announcements (`aria-label`, `aria-live="polite"`).
2. **Notification Dropdown Preview (Desktop/Tablet):**
   - Popover displaying the 5 most recent alerts, unread highlight bars, relative Ghana-time (`Africa/Accra`) timestamps, "Mark all as read" button, and direct link to full inbox.
3. **Mobile 360px Touch-First Behavior:**
   - Avoids cramped popover overlays on <= 640px devices; tapping the bell smoothly transitions directly to `/notifications` with no horizontal overflow at 360px width.
4. **Full Notification Inbox (`/notifications`):**
   - Event category badges: Verification (`ShieldCheck`), Listing (`Home`), Staff (`Users`), and Security/Account (`AlertTriangle`).
   - Deep-link routing matrix mapping each notification event to its target portal page (e.g., `/owner/verification`, `/owner/listings/:id/edit`, `/admin/approvals/:id`).
   - Ghana-time (`Africa/Accra`, GMT+0) timestamp formatting.
5. **Component States:**
   - Loading skeletons matching real row heights.
   - Empty state: *"You're all caught up!"* with friendly graphic and Return to Dashboard action.
   - Error/retry state: *"Unable to load notifications"* with connection retry button.
6. **Backend Contract Alignment:**
   - Fully mapped to canonical endpoints implemented in `S1-10-T5` (`GET /api/v1/me/notifications`, `POST /api/v1/me/notifications/{id}/read`, `POST /api/v1/me/notifications/read-all`).
