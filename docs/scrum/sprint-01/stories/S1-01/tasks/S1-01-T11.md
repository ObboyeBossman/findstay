## What this task really means

You build the automatic checker-and-publisher that guards quality: whenever anyone proposes a change, it automatically builds the app, runs all the tests (including the check that no part of the system secretly reaches into another part), and — only if everything is green — publishes to staging. After your work, nobody can break staging unnoticed, and every change shows a green or red mark.

## What you will have at the end

- Every change automatically built, tested and published to staging on green.
- A visible green/red status on every proposal — quality is guarded by the robot, not by memory.

## Checklist

- [x] Create the pipeline that runs on every change and proposal. — `.github/workflows/ci.yml`: `pull_request` (every proposal) and `push` to `staging` (the publish trigger), with concurrency cancellation.
- [x] Make it build the app and run all tests automatically. — the `web` job typechecks and production-builds the React app; the `api` job runs `mvn test` — the full suite including the Testcontainers throwaway-database tests and the `@Req` check.
- [x] Include the check that modules do not reach into each other. — `ApplicationModules.verify()` runs inside `mvn test` (the Modulith boundary check, sprint invariant C5) — a boundary violation turns the proposal red.
- [x] Publish to staging only when everything is green. — the `publish` job needs both jobs green and runs only on `staging` pushes: the website is built with the staging API URL and published to Cloudflare Workers (wrangler — needs the `CLOUDFLARE_API_TOKEN` repo secret; until it is added the step skips with a visible warning), and the Render deployment is *verified*: the job waits for a **new build time** on `/actuator/info` and a green `/actuator/health`, else it fails. The API publishes itself — Render auto-deploys the `staging` branch; CI guarantees only green code reaches it (`dev` protected: both checks required).
- [x] Show the green/red status on every proposal. — proven on PR #47 itself: green checks reported on the proposal ([run 44122531350](https://github.com/ObboyeBossman/findstay/actions/runs/44122531350)); `dev` branch protection now makes both checks *required*, so an unreviewed red proposal cannot merge.
