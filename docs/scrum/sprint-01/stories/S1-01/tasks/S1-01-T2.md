## What this task really means (plain English)

You choose the overall look of FindStay: which colors, which fonts, how big text and spacing are. You record every choice as a named value (called a “design token”) in one style file. Because every screen will take its look from that one file, swapping a color or font later means changing it in one place and the whole app updates automatically — that is exactly why the Product Owner wants this in your hands.

## What you will have at the end

- One style file (the design tokens) listing FindStay's approved colors, text styles and spacing.
- Every screen built after you reads from this file — and any future restyle is a one-place swap.

## Checklist

- [ ] Pick the color set: main, accent, background, text, success/error.
- [ ] Pick the fonts and text sizes for headings and body.
- [ ] Pick the spacing steps (small, medium, large gaps).
- [ ] Record every choice as a named value in the one style file.
- [ ] Apply the style file to the starter app so screens can use it right away.
