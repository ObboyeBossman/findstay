## What this task really means (plain English)

You set up where and how the team works: one repository holding all the code; rules that protect the main branch so nothing unreviewed gets in; safe storage for the secret keys; and the staging site — the live address where the team's combined work gets published for review. After your work, “the project” physically exists and is reachable.

## What you will have at the end

- One protected code repository with secrets safely stored.
- A working staging site where every accepted change is published for the team to review.

## Checklist

- [ ] Set up the single repository structure (one home for all code).
- [ ] Protect the main branch: changes enter only through reviewed proposals.
- [ ] Store the secret keys safely (never in code).
- [ ] Create the staging site, server and database.
- [ ] Prove a test change lands on staging.
