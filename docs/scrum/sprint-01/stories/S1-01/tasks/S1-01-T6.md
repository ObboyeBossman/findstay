## What this task really means

You draw the map of the system's back end: the big parts of FindStay (accounts, listings, bookings, payments, admin and so on) and — most importantly — how information moves: what the screens send in, how each part processes it, what goes to the database, and what comes back out. You then write down, for every part, the exact agreement of what it accepts and returns, so the frontend and backend people build against the same contract. The Product Owner is keeping this one personally to own the backend flow.

## What you will have at the end

- The backend map / data-flow diagram: one picture of the system's parts and how data travels between screens, parts and the database.
- The API agreement documents for every part: what it accepts, what it returns — the contracts frontend and backend both build against.
