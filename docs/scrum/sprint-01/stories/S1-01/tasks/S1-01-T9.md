## What this task really means (plain English)

You turn the agreed database diagram (ERD) into the real database on the hosting service: you create the separate sections (one per part of the system) and you write the numbered setup scripts that build every table. These numbered scripts are the only way the database ever changes, so every copy of the system — on a laptop, staging, or live — ends up identical.

## What you will have at the end

- The staging database actually existing, with the full Sprint 1 structure.
- It was created purely by the numbered scripts (V1_01–V1_19) and matches the approved ERD exactly — same script, same database, everywhere.
