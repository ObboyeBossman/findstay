# Documentation agent guide

`docs/` is the approved product, technical, and delivery record—not supporting copy. Preserve requirement IDs, requirement-to-story traceability, settled decisions, and completed sprint evidence unless the request explicitly changes them.

## Fast routing

- `overview.md` — product, audience, phase, and repository map.
- `requirements/` — authoritative functional, non-functional, business, technical, and use-case requirements.
- `rules/` — architecture/security rules, module boundaries, and compatibility contract.
- `scrum/` — sprint plans, story acceptance criteria, delivery gates, and decisions.
- `evidence/` — facts produced by completed work or an explicit project sync; do not invent results.
- `team/` and `meeting-notes/` — attribution and historical records; edit only with a clear request.

Prefer focused edits that retain existing Markdown links and identifiers. When implementation changes a promise, update the relevant requirement, acceptance criterion, decision, or evidence deliberately rather than rewriting broad documentation.
