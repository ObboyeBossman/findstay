# 03 — Architecture, Stack & Security Rules

## 1. Approved Technology Stack

- **Frontend (`apps/web`, `apps/site`):** React + TypeScript + Vite deployed to **Cloudflare Workers Static Assets**. Responsive mobile-first web UI (`CON-01`, `NFR-11`, `NFR-12`). No native mobile app in scope (`CON-04`).
- **Backend (`apps/api`):** **Java 21 + Spring Boot 3** modular monolith (`Spring Modulith`) deployed on **Render** (non-sleeping plan from Sprint 2; health-pinged in Sprint 1).
- **Database, Auth & File Storage:** **Supabase** (PostgreSQL 15+, Supabase Auth, Supabase Storage).
- **Database Migrations:** **Flyway** managed exclusively by the Spring Boot backend (`src/main/resources/db/migration`).

---

## 2. Data Access & Authentication Boundaries

1. **No Direct Frontend Data API Access:** The browser talks to Supabase **only** for Auth (`supabase.auth.*`). All business data reads/writes and signed storage URL requests go through the Spring Boot REST API (`/api/v1/...`). Supabase PostgREST / Data API access to application tables is disabled or locked down via RLS so the service role / backend connection is the sole data gateway.
2. **JWT Verification via JWKS:** The Spring Boot resource server validates every incoming `Authorization: Bearer <token>` against Supabase's JWKS endpoint (`SEC-01`, `SEC-02`) and maps the authenticated user's active organisation membership and role permissions into the request security context.
3. **Multi-Tenant Isolation (`OrgScope`):** Every owner's properties, units, documents, bookings, and staff memberships belong to an `organization_id` (`J-06`). Repository queries and service methods must enforce `OrgScope` so Owner A can never read or mutate Owner B's records (verified by automated cross-tenant negative tests in `R1`–`R5`).

---

## 3. Domain & Data Integrity Conventions

1. **Money in Integer Pesewas (`BRL-01`):** All monetary amounts (rates, fees, payouts, refunds) are stored and calculated as `BIGINT` integer **pesewas** (`1 GHS = 100 pesewas`) paired with `currency = 'GHS'`. Floating-point types (`FLOAT`, `DOUBLE`) are forbidden for money.
2. **Time in UTC, Displayed in `Africa/Accra`:** All timestamps are persisted as `TIMESTAMPTZ` in UTC and formatted in `Africa/Accra` (`GMT+0`) at the presentation boundary.
3. **Append-Only Audit Trail (`SEC-04`):** Sensitive actions (role changes, verification decisions, listing approvals/rejections, account suspensions/restorations, payout approvals) must write an immutable record via `AuditRecorder`. Audit rows cannot be updated or deleted by application users.
4. **Encryption & PII Protection (`SEC-03`, `SEC-06`, Act 843):**
   - TLS 1.2+ in transit for all endpoints (`SEC-02`).
   - Government ID numbers (e.g., Ghana Card numbers) and sensitive verification identifiers are encrypted at rest with AES-256 before persistence (`SEC-03`).
   - Verification documents and property deeds are stored in private Supabase Storage buckets and accessed only via short-lived signed URLs generated by the backend after authorization checks.
   - Images uploaded for listings are validated for MIME/size limits and served as optimized `WebP` (`NFR-13`).
